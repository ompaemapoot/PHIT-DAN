# USB? Game prototype

Run a local static server from this directory, for example:

```sh
python -m http.server 8000 --bind 127.0.0.1
```

Open `http://localhost:8000/index.html` to play. To play on a phone over the same Wi-Fi, bind to all interfaces instead, for example `python -m http.server 8000 --bind 0.0.0.0`, and open `http://<computer LAN IP>:8000/` on the phone. This exposes files in the served directory to devices that can reach the server; use it only on a trusted network and stop the server when finished. Windows may ask to allow Python through the firewall for private networks; Wi-Fi networks with client isolation block phone-to-computer access. Open `http://localhost:8000/transition-preview.html` separately to test the transition examples; the game has no link to that separate page. The game and examples load Three.js r164 from the local `vendor/three.module.min.js` copy (MIT; the license sits beside it). DM Sans and Kanit are self-hosted under the SIL Open Font License; their notices are in `assets/fonts/DM-SANS-OFL.txt` and `assets/fonts/KANIT-OFL.txt`. The fonts are self-hosted: the woff2 subsets live in `assets/fonts/` and are declared in `fonts.css`, so the page makes no third-party requests and works offline once loaded. Without the font files the text falls back to system fonts and the game still runs. Enter a player name before playing; the name is remembered locally and appears next to each run's score. Play again keeps the same name, while Menu returns to the start screen to enter another. On the start screen, use the Leaderboard button to open a separate score view; the Back to menu button sits below the list and returns to the menu. All ten positions are shown, with a dash for each empty position. After a game, the leaderboard appears automatically and highlights the latest run, below the list if outside the top 10; the instructions are hidden on the game-over screen. Tied scores rank in the order achieved. Scores saved before names were introduced remain as `Unknown`; older discarded scores cannot be recovered. The leaderboard and name are local to the browser and site origin, not shared online; clearing site data removes them. If storage is unavailable, scores last only until the page is closed or reloaded. No names or scores are sent to an application server, and every asset the page needs is served from this folder.

The game runs on desktop and phone browsers and uses the full viewport with safe-area padding. On a touch device it is portrait-only: rotating a phone or tablet to landscape covers the game with a rotate-to-portrait panel and pauses the run until the device is upright again. A web page cannot change the operating system orientation lock, so this panel is the enforceable equivalent. On a short landscape screen that is not gated, such as a small desktop window, the menu hides the decorative orientation examples and shortens its rows so Play stays above the fold. A run pauses whenever the page or app loses focus or becomes hidden: a phone call, an app switch, the lock screen, another window or a system dialog covers the playfield with a **Paused** panel. Every countdown, automatic insertion, target shift, Beat phase and animation stops, so nothing is lost while the panel is up. Tap **Continue** to start a 3-2-1 countdown, then the remaining time goes back on the clock, so there is a moment to pick up the rhythm again; returning to the page never restarts the run by itself. The portrait panel still resumes by itself once the device is upright. While the menu, the rotate panel or the pause panel covers the playfield the 3D scene is not redrawn.

The interface is in English. A game-over message explains that the USB was facing the wrong way.

After a manual game, the result screen offers two share controls and does not preview the score card. Share link opens the device share sheet with the run's message and the current game URL; when sharing is unavailable, the link is copied to the clipboard, and if clipboard access is also blocked the status line asks the player to download the image instead. Download image saves the locally generated PNG score card for attaching elsewhere; the image is not shown on the result screen. The card is a 1080×1350 portrait graphic in the Slate + Cobalt light palette: the start-screen PHIT DAN wordmark in the header, a mode chip, the score in large tabular numerals above POINTS and a gold contact mark, and a cobalt footer with a ghosted copy of the full logo lockup, a USB drive inside a 180-degree flip arrow, the tag line and the game's host name. The card carries no QR code. Apps may handle the shared message and link differently. The image does not include the player's name, and no score is sent to an application server; the player chooses where to share. The game must be published at a publicly accessible URL for other people to follow the link; localhost links work only on the current machine.



The game uses the fixed Slate + Cobalt light palette. Open **Settings** on the main menu to toggle **Sound on/off** in its own menu view, which has a Back button and replaces the other menu rows instead of floating over them; Settings is hidden on the Game Over screen. Sound can be changed before each run. Theme selection is not available. **Clear my data** in the same panel asks for confirmation, removes this browser's saved player name, all three leaderboards, the saved messages and the sound and message switches, then reloads the page. It only deletes keys that start with `phit-dan-`, so other site data is left alone, and nothing is sent to a server.

Below Settings, **Info** opens the same kind of menu view and holds three link sections. My links, GitHub and Feedback start inactive with no addresses included. To enable one, set `infoLinksUrl`, `infoGithubUrl` or `infoFeedbackUrl` in `game.js`. Configured links open in a new tab. Under Back, one quiet footnote reads the version from `gameVersion` in `game.js`, credits three.js under the MIT licence and repeats that scores stay in this browser. Info is hidden during a run, on the Game Over screen and while the mode choices are open.

Link previews: `index.html` carries Open Graph and Twitter card tags that point at `assets/og-card.png`, a 1200 by 630 preview card in the same palette. The image path is relative, which resolves on any host that serves the page; if a platform refuses relative image paths, replace `og:image` and `twitter:image` with the full published URL. The game source is available under the MIT licence in the repository root `LICENSE` (Copyright 2026 Ompaemapoot), and the bundled three.js keeps its own MIT notice in `vendor/THREE-LICENSE.txt`, which is credited in the Info footnote.

Installable app: `manifest.webmanifest` declares the name, a standalone display, portrait orientation, the Slate + Cobalt theme colours and 192 and 512 px icons plus a maskable copy drawn from the same USB mark; `assets/apple-touch-icon.png` (180 px) covers iOS home-screen installs. On a phone, use **Add to Home Screen** and the game opens without browser chrome. Icons, manifest and the self-hosted font subsets all come from this folder.

**Player messages** are a light taunt system, stored only in this browser. A run that scores at least one point shows a Leave a message panel on the result screen: type up to 60 characters and press Post, and the message is saved with that score, the mode and the player's name. During play, when the player's score crosses a saved score in the same mode, one saved message appears as plain theme-coloured text in the empty column to the left of the hub, with the author name and the score on their own quieter line underneath, kept apart from the message by a stacked layout and a thin rule. It stays for about seven seconds, then clears; a later crossing can show another message. There is no card or 3D texture to get in the way of the drive. Hub, Rail and Beat keep separate score scales, so a message only appears in the mode it was left in. **Settings** has a Player messages on/off switch that hides both the in-play messages and the game-over composer; the default is on. Nothing is sent to a server, and clearing site data removes the saved messages.

**Beat** is a regular mode beside Hub and Rail, with its own local leaderboard and score card. It requires a player name for manual play. There is no visible FLIP or INSERT button: tap or click the game area, or press Space, before the flip deadline expires. During the separate insertion phase, tap or click the game area or press Space as the bouncing marker crosses the GOOD or narrower PERFECT timing band. The top rail visibly drains during both phases; timer text remains available to screen readers while visible numeric countdowns are omitted. The initial insertion deadline allows three cursor traversals and has not yet been player-tuned. Missing either deadline, inserting outside the GOOD band, or having the wrong USB orientation ends the run. PERFECT timing gives bonus points. Consecutive perfect insertions raise the bonus every three hits, up to four times the base bonus. The marker speeds up and both timing windows tighten as the run score rises. Play again repeats Beat; Menu returns to choose another mode.

The start screen stacks its controls in one column, and **Play**, **Leaderboard**, and **Settings** share the same full-width button style. Enter a player name first: **Play** opens the mode choices only when a name is present and reports a missing name on the first screen, and the name field leaves the screen once the choices are open. Press **Hub**, **Rail**, or **Beat** to begin that mode immediately; the expanded mode view shows only the three modes and a Back button, while Play hides itself. Leaderboard and Settings stay on the first screen, and Back returns to them. The display names Hub, Rail, and Beat do not change the internal mode identifiers `arcade`, `horizontal`, and `timing`, their leaderboard storage keys, or gameplay. Rail has a continuous, evenly spaced line of horizontal sockets; drives fill them one by one, with the next socket visible in advance. The target stays still during the countdown and the player only decides whether to flip the drive. Rail normally starts with a 1.1-second countdown, 0.2-second insertion, 0.08-second success pause, 0.38-second scroll and 0.19-second entrance. All of these shorten as the score increases, with minimums of 0.35, 0.11, 0.04, 0.14 and 0.08 seconds respectively. Hub starts with a 0.26-second insertion, 0.11-second success pause, 0.56-second scroll and 0.28-second entrance; these gradually shorten with score. Its countdown follows the gentler curve below. Beat uses Hub's progressive layouts and round pacing, while requiring a flip every round followed by a timed insertion. Each mode has a separate local leaderboard; switch modes using the three buttons in the leaderboard view. Play again retains the mode; Menu returns to the menu where a different mode can be started.

Successful insertions in Hub and Rail update the upper-left score, briefly pulse the number in cobalt, and show a compact **CORRECT +1** badge below the score; there is no central impact flash. Beat shows a compact GOOD/PERFECT grade badge with the awarded points. A short, quiet synthesized mechanical-style click and rising mid-high confirmation tone provide audio feedback. The sound toggle is in **Settings** on the start screen, and no audio files are downloaded. Major score milestones keep a separate rising audio cue, but no popup text; progression thresholds remain visible through changes to the port layout and speed. These cues do not change any mode's scoring or timing rules.

The two retention holes on the metal plug belong on the opposite side from the blue tongue in the port. In Hub and Rail, tap or click the play area, or press Space, to flip the drive; insertion remains automatic. Rail's normal countdown starts at 1.1 seconds and decreases by 0.025 seconds per point to a minimum of 0.35 seconds. Hub's normal countdown starts at 1.155 seconds and decreases by 0.012 seconds per point to a minimum of 0.7 seconds. One incorrect insertion ends the game; the player can replay. After a correct insertion, the sockets and inserted drives move down a continuous hub extending beyond the bottom of the screen, and a new drive enters after the next sockets arrive. Scrolling and entrance also speed up with score. Older drives and their sockets leave together through the bottom of the viewport without fading. The countdown and flip input resume only after the new drive is in place. The initial port face and whether a flip is needed are randomized, but neither initial flip-needed nor no-flip-needed can occur more than twice consecutively. A Hub target change can alter which answer is correct. The drive automatically follows the target port's axis, so the player only decides whether to flip it 180 degrees.

In Hub, the first four points use horizontal ports; a vertical port appears at four points. At 8 points, paired ports appear; at 16 points, three horizontal or vertical ports appear; at 24 points, a two-row grid of three vertical ports appears; at 32 points, a two-by-two grid mixes horizontal and vertical ports. From 48 points, multi-socket rounds have a 35% chance of the drive shifting automatically to a different socket during the countdown, increasing to 60% from 72 points. Rounds selected for a shift get 500 ms extra, yielding 1,200 ms at those scores, and the shift begins 20% of the way through that countdown; the countdown does not restart. If a delayed switch would leave less than 800 ms, it is skipped. Milestones use a rising sound cue without popup text; there is no added pause and the countdown is unchanged. The drive points at the target; other sockets are decoys and may face differently. Thresholds and probabilities are playtest settings.

The camera is zoomed in to emphasize the active drive and roughly one previous drive; the number visible depends on screen proportions. The unframed score is in the upper-left corner; the countdown bar sits slightly right of center and drains from left to right. All three modes share one countdown bar: an ink-navy rail that warms to brass at half time and to muted red in the last quarter, on a pale slate track. Beat adds a steel-blue GOOD band and a narrow brass PERFECT core with a contrasting outline, plus a pale needle edged in ink so it reads over both the rail and the track. Shrinking geometry also communicates remaining time, so the cue does not depend on color or visible digits. The same bar runs during both Beat phases, alongside the separate cyan bouncing insertion marker. A small rectangular light on the drive's end cap stays green after a correct insertion and stays red after a mistake; mistakes briefly shake the drive before game over. Success pulses the score number and plays a short generated confirmation cue; stage milestones use a separate ascending cue without popup text. The sound can be disabled in the main-menu Settings menu, and the timer's numeric text remains in its assistive-technology-only timer element; a separate live region announces results. With reduced motion, the failure shake and celebration animations are suppressed; the score still updates without motion.

The separate `transition-preview.html` page automatically compares seven transitions: stationary-hub socket cover, whole-scene slide, two-faced hub flip, flip with the away-facing side hidden, a physically occluding thick hub, frame cross-dissolve, and a continuous vertical hub with older drives scrolling off the bottom edge. The preview uses representative timing and examples; it does not change the playable game. Its buttons switch examples or pause the loop.
